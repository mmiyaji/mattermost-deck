# メンションの編集・削除反映（2026-11-03）

## 変更

- 再起動時に読み込んだキャッシュ投稿も、既存の投稿ID一括確認に含める。
- チームの未読件数が変わらず取得結果を再利用する場合も、保持済み投稿を一括確認して編集・削除を反映する。新しい検索結果に含まれる投稿は重複確認しない。
- 既存の表示行には検証済みの本文変更・削除を反映し、新着行の挿入は従来の更新案内で保留する。新着が存在しても古い本文の更新を妨げない。
- キャッシュだけにあった投稿が検索範囲外でも、ID確認で存在すれば保持する。確認が失敗した場合も既存本文を保持する。
- 再利用するチーム結果へも確認結果を反映し、古い本文・削除済み投稿の復活を防ぐ。
- `delete_at > 0` は明示的な削除情報として、要確認データにも削除印を反映する。確認済み判断と削除された投稿IDの記録を保持する。削除済み本文は既存の剪定対象。単にIDが返らない場合は永続的な削除と断定しない。
- 要確認データの削除対象判定は、描画時点のスナップショットではなく保存キュー内の最新データで行う。読み込み中に登録された投稿の削除漏れと、無関係な削除印の追加を防ぐ。
- 遅れて返る古いポーリング本文で新しいWebSocket編集を上書きしないよう、本文バージョンを比較する。

## WebSocket

削除通知を受けてライブ一覧・表示保留中の一覧・保存済みキャッシュ・要確認一覧を除外する既存経路は、修正前から動作していた。不要な再実装はせず、本番拡張と実ソケット接続のE2Eを追加した。

確認対象は通常／要確認共有、確認済み履歴の編集反映、確認判断の維持、削除時の保存キャッシュ無効化、削除前に始まったポーリングの遅延応答、再取得・再読み込み後の非復活。
