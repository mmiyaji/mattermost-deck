# メンション表示キャッシュの保存方式

設定値は `chrome.storage.local`、投稿の表示キャッシュは拡張機能のサービスワーカーが管理する IndexedDB に保存する。取得完了後の一覧から軽量なスナップショットを作り、次回の再取得中に表示する。未確認投稿・確認済みの判断を保持するストアとは分離する。

## 保存先の比較

| 保存先 | 特徴 | この用途での判断 |
| --- | --- | --- |
| `chrome.storage.session` | メモリー上。拡張更新・再読み込み・ブラウザー終了で消える。通常10MB | 永続保存を明示的に無効にした場合に使う |
| `chrome.storage.local` | 拡張内で共有でき、変更通知を持つ。通常10MBを設定や他のデータと共有 | 設定に使う。本文の多数保存には容量競合と大きな値の書き直しが不向き |
| IndexedDB | 非同期の構造化データ保存、キー単位の取得、トランザクションが使える | 本文キャッシュに採用。データと管理情報を別ストアにする |
| Cache Storage | Request / Response の組を保存する用途 | 取得条件・既読状態を含む一覧スナップショットにはIndexedDBの方が扱いやすい |

Chrome公式は `storage` の容量と保存コストを説明し、コンテンツスクリプトのWebストレージはホストページ側の領域になると明記している。そのため、コンテンツスクリプトで直接IndexedDBを開かず、メッセージで拡張サービスワーカーへ依頼する。

- [Chrome Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)
- [Chrome: Storage and cookies](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies)
- [MDN: IndexedDB API](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API)

## 上限と更新

- 永続保存は未設定の場合に有効。既存の明示的な無効設定は維持する。
- 取得範囲はサーバー・アカウント・対象チームで識別し、チーム一覧とメンション条件も読み込み時に照合する。同一取得範囲の通常／要確認ペインは同じスナップショットを使う。
- 各範囲は最新100件・本文データ240KiB以内。添付本体や画像は保存しない。
- 永続保存は最大64範囲・スナップショット合計16MiB・保存から24時間。上限を超える場合は使用の古い範囲から削除する。
- IndexedDBの本文と容量・使用時刻の管理情報を分離し、通常の保存時に全範囲の本文を読み直さない。容量の判定にはスナップショットJSONのUTF-8バイト数を使う。16MiBはDBファイルそのもののディスクサイズではない。
- 容量管理と更新はトランザクションで実施する。期限切れの物理削除は次のキャッシュ操作時に行う。
- 旧 `chrome.storage.local` のキャッシュは移行がコミットした後に削除する。失敗した場合は旧データを残す。
- 保存失敗は取得処理を止めず、次回はキャッシュなしで通常取得する。容量不足時に `chrome.storage.local` へ本文を書き戻すことはしない。
- 永続保存を無効にした場合はセッション保存のみを使い、最大64範囲・合計4MiB・表示期限15分とする。

キャッシュは再取得を省略する根拠には使わない。表示中の内容は前回取得時点のものであり、最新の投稿・削除・既読状態はサーバーとの照合で反映する。本文に独自の暗号化は追加しない。IndexedDBもブラウザーによる削除や容量不足があり得るため、キャッシュを永続的な正本として扱わない。
