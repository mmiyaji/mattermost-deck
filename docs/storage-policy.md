# ストアとキャッシュの保持方針

利用者の判断を保持するデータと、再取得できる表示データを分ける。キャッシュの容量整理や期限切れを理由に、お気に入り登録・未確認投稿・確認済み判断・除外設定を削除しない。

| 用途 | 保存先 | 制限・無効化 |
| --- | --- | --- |
| 設定・レイアウト・除外ルール | `chrome.storage.local` | 明示的な保存・削除。実行中の拡張の保存失敗は通知し、ページ側localStorageへ切り替えない |
| お気に入り登録 | `chrome.storage.local` | サーバー・アカウント別、100件。本文と分離し、登録世代で解除・再登録を識別 |
| 未確認投稿・確認済み判断 | 拡張側IndexedDB | 表示キャッシュのLRU・TTLの対象外 |
| メンション表示用本文 | 拡張側IndexedDB | 最大64取得範囲・本文等のスナップショット合計16MiB・24時間 |
| お気に入り本文 | 拡張側IndexedDB | 全体16MiB・5000件・最終確認から7日。本文期限切れ・削除・取得不可でも登録は保持 |
| メンションのセッション表示 | `chrome.storage.session`、背景側で更新を集約 | 最大64範囲・4MiB・15分。削除世代もセッションに保存 |
| 診断ログ | 背景側の単一書き込みで`chrome.storage.local` | 500件・24時間・合計約1MiB。1件16KiB、クリア・記録停止で世代を更新 |
| API応答・ユーザー／チャンネル辞書 | メモリー | メタデータ5分、辞書2000件。アカウント変更時は世代を切り替え、旧応答を拒否 |

バイト上限はシリアライズしたデータのUTF-8サイズに基づく。DBファイル自体のディスク占有サイズとは異なる。TTLによる物理削除は次のストア操作時に行う。

## 更新の整合性

- コンテンツスクリプトからIndexedDBを直接開かず、拡張サービスワーカーへメッセージで依頼する。
- お気に入りの本文更新は登録世代、取得開始時刻、投稿の更新日時で判定する。遅い古い応答は新しい本文を上書きしない。
- 投稿削除通知では本文を直ちに無効化し、進行中の取得や別タブからの保存で復活させない。
- セッションキャッシュの削除世代はWorker再起動後も維持し、対象キャッシュのTTL経過後に整理する。世代情報の上限到達時は、表示キャッシュの保存を保守的に拒否する範囲を広げる。
- 診断ログはタブごとの配列置換を廃止し、背景側で追記する。安定したイベントIDで再送を重複排除し、クリア前の遅延バッチは世代で拒否する。
- UI辞書はサーバー・アカウント・メタデータ世代で分離する。ユーザー更新イベントを反映し、その前に開始した辞書取得の古い応答は拒否する。

## 移行と失敗

お気に入りの旧本文はIndexedDBへの保存が成功してから旧領域から除去する。移行中の失敗で登録情報や旧本文を失わない。キャッシュを保存できなくても登録操作は保持できる。

設定の保存失敗は呼び出し元へ返し、設定画面やDeckの通知で表示する。読み込みに失敗した初期値を自動保存しない。設定画面の再試行は、再読み込み成功まで保存を許可しない。

キャッシュや診断ログの失敗は通常の閲覧処理を停止させない。メモリー内の表示を維持し、再取得できる状態として扱う。設定・お気に入り登録・確認判断の保存失敗と区別する。
