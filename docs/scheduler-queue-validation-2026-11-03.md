# APIスケジューラの全件走査解消（2026-11-03）

## 変更

- 優先度3種 × GET/POSTの6系列へ分割。候補選択は各系列の先頭だけを比較する。
- 元の到着順を保持する索引付きヒープで、途中キャンセルと優先度昇格も全件走査を避ける。追加・削除は O(log n)、候補比較は最大6件。
- 同一優先度内では実行可能なものをFIFOで選ぶ。2秒以上待った非interactiveの救済は4回に1回のルールを維持。
- レート待ち時間はGET/POST別の累積時計から算出。同時実行枠だけが原因の待ち時間と区別する。件数などのキュー診断にも全件走査を使わない。
- 並列数の設定変更時はクールダウンをリセット。同値の再設定では制御状態を維持する。
- 応答時間の直近32サンプルは整列済み窓を差分更新し、毎応答のコピー・ソートをなくす。従来の20パーセンタイル・平滑化・並列数判断は維持。
- 待ち行列タイムアウトには既に個別タイマーがあるため、本体の方式変更は不要。実行枠を塞いだままでも期限どおり拒否し、その後fetchされない回帰テストを追加。

## 検証

- 型チェック、全675単体テスト、拡張ビルドが成功。
- 2万件のキューで、先頭取得・件数・最古時刻・途中削除・特定キーの昇格が無関係なノードを走査しないことを検証。
- 5千回の追加・昇格・削除を参照モデルと照合。適応制御も重複を含む2,560サンプルで従来方式と照合。
- レート待ち途中に参加したリクエストの待ち時間と、GET制限中のPOST通過を検証。同時実行枠待ちがレート待ちとして記録されないことを検証。
- Docker Mattermostで13チーム・78未読スレッド・117メンションのE2Eが成功（約2.1分）。初回取得33,744 ms、ブラウザ再起動後のキャッシュ初期表示2,189 ms／91件。投稿追加、確認操作、再起動、既読処理、削除、自分の投稿の除外で投稿ID・件数バッジを照合し、取りこぼしなし。これらは変更後の実測であり、環境差を含むため前後の速度改善を示す数値としては扱わない。
